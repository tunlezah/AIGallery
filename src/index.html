How to get a project listed

{{TOPIC_STATUS}}

Help: getting into the gallery

Two ways in. Merge request: add a curated entry to the content repository — for anything with a link; the gallery’s maintainers review it. GitLab topic: tag your own project on {{TOPIC_INSTANCE_HOST}} and it lists itself — no review, refreshed on every build.

Entries are added to the content repository by merge request and reviewed by the gallery’s maintainers.

Add a curated entry by merge request

Curated entries live in the content repository, a separate Git repository from this site. Anything with a link can be listed; the gallery’s maintainers review every change.

  1. Fork or branch the content repository.
  2. Pick a section — a top-level directory — or create one. An optional _section.md gives a section its title, order, description and icon.
  3. Inside the section, add one directory for your entry with an index.md in it. The directory name becomes the entry’s slug (lower-case letters, digits and hyphens) and must be unique within the section.
  4. Open a merge request. Once it is merged, the gallery’s next build validates the entry and shows it.
tooling/                    <- section (top-level directory)
├─ _section.md              <- optional: title, order, description, icon
├─ icon.png                 <- optional section icon
└─ my-tool/                 <- your entry (directory name = slug)
   ├─ index.md              <- REQUIRED
   └─ cover.png             <- optional card image

What goes in index.md

---
title: "My Tool"                # REQUIRED: the card title
url: "https://example.com"      # optional: link on the title; http(s) or relative
image: "cover.png"              # optional: file in this directory; omit for the default image
tags: ["local", "cli"]          # optional: chips and filters
summary: "One line, 200 chars." # optional: derived from the body if omitted
order: 10                       # optional: sort weight, lower first (default 1000)
added: 2026-03-14               # optional: ISO date
updated: 2026-08-01             # optional: ISO date, shown on the card
featured: false                 # optional: true adds a Featured badge
draft: false                    # optional: true leaves the entry out
---

Fails the build: a missing title, malformed frontmatter, a link with any scheme other than http(s), an image path outside the entry’s directory, an SVG with active content, or two directories in one section with the same slug. Warns only: a missing image file (the default image is used), unknown fields, invalid dates. This gallery builds in strict mode, so warnings fail the build too.

To change an entry, edit its index.md or replace its image and open a merge request. To remove one, delete its directory or set draft: true.

List your own project with the GitLab topic

Any project on {{TOPIC_INSTANCE_HOST}} can list itself without a merge request: on every build the gallery asks GitLab for the projects carrying the topic {{TOPIC_NAME}} and turns each one into a card in the {{TOPIC_SECTION_TITLE}} section.

  1. Open your project’s Settings → General and expand Naming, topics, avatar.
  2. Add the topic {{TOPIC_NAME}}, spelled exactly like that, and save.
  3. Wait for the next gallery build (scheduled, or triggered by the maintainers). The footer of this page says how many tagged projects the last build found.

Required

  • The project is hosted on {{TOPIC_INSTANCE_HOST}} — the GitLab instance this gallery reads.
  • The topic {{TOPIC_NAME}} is on the project.
    • {{TOPIC_ELIGIBILITY_RULES}}
  • The project is not already a curated entry: a tagged project whose URL or slug matches a curated entry is dropped, and the curated entry wins.

Nothing else is needed. These project settings shape the card:

Optional — a manifest for full control

Commit {{TOPIC_MANIFEST_PATH}} on your default branch, in the same format as a curated index.md. Every field is optional and replaces the value derived from the project:

---
title: "Prompt Forge"           # replaces the project name
summary: "Prompt versioning."   # replaces the description (200 chars)
tags: ["prompts", "cli"]        # replaces the tags derived from topics
image: "cover.png"              # PNG/JPEG/WebP/GIF next to this file; beats the avatar
url: "https://<instance>/group/project/-/releases"   # must stay on {{TOPIC_INSTANCE_HOST}}
order: 10                       # position in the curated sort
added: 2026-03-14
updated: 2026-08-01
featured: true                  # adds the Featured badge
draft: false                    # true removes the project from the gallery
---
Markdown body, shown on the card instead of the description.

The manifest is read from the default branch and may be at most 256 KB. image must be a raster file in the manifest’s directory or below it, up to {{TOPIC_AVATAR_MAX_KB}} KB — no SVG, no URLs, no ... The body is sanitised like every other card body.

Leaving the gallery

Remove the topic, or set draft: true in the manifest. The card disappears on the next build.

Not showing up?

  • The gallery has not been rebuilt since you added the topic. New projects appear only after the next build.
  • The topic is misspelled, or the settings page was not saved.
  • The project fails one of the rules under Required above.
  • It duplicates a curated entry’s URL or slug; the curated entry wins.
  • Its manifest sets draft: true.
  • The topic feed was unavailable when the gallery was built (the footer says so), or the list was cut off at {{TOPIC_MAX_PROJECTS}} projects.

Search, filters and settings

Searching matches titles, summaries, bodies, tags and section names, ignoring accents and case. Filters combine with the search: click a section or a tag chip in the sidebar (or a chip on a card) to narrow the gallery down, and Clear all filters to start over.

Search prefixes

tag:localOnly items carrying that tag.
section:toolingOnly items in that section, by its slug.
source:topicOnly projects discovered via the GitLab topic; source:content for curated entries.
is:featuredOnly featured items.

Prefixes combine with plain words, for example tag:local vector.

Keyboard

/ jumps to the search box and Esc clears it. In this dialog, ← and → switch tabs and Esc closes it.

Sharing a view

The address bar carries the current search and filters, so copying the URL shares exactly what you see. Adding #help to the gallery’s address opens this dialog, and #help=topic opens it on the GitLab topic tab.

Settings

The gear button sets the theme (System, Light, Dark or GeoCities), the sort order (curated order, title, date added or date updated) and the tile density. Choices are remembered in this browser only.
